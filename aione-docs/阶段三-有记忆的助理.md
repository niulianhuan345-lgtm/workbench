# 阶段三-有记忆的助理



---

## 3.1 操作历史记忆 — 需求文档

> 日期：2026-05-26 | 类型：执行级需求文档 | 阶段：三
>
> 目标读者：研发团队。AIONE 记住每次操作的背景和结果，下次遇到类似情况时主动引用历史经验，避免重复犯错。

---

## 一、功能定义

### 1.1 一句话

AIONE 记住你做过的每次操作——调了什么、当时什么情况、后来效果怎么样。下次类似场景出现时，他主动引用："上次类似情况你降了出价，ROI 涨了 30%，这次建议同样操作。"

### 1.2 产品形态

不是独立功能，是渗透在所有交互中的记忆层。体现为：

| 场景 | AIONE 行为 |
|------|----------|
| 运营又要调同一个词 | "上个月你把这个词从 ¥3.5 降到 ¥2.8，ROI 从 1.2 回到 1.8。这次条件类似，建议同样幅度。" |
| 运营问优化建议 | "根据历史记录，你通常会在 ROI < 1.5 且花费 > ¥500 时介入。当前有 3 个计划满足条件。" |
| 运营要暂停计划 | "这个计划你 3 月暂停过一次，当时是因为 CPC 暴涨。现在 CPC 正常，确定要停吗？" |
| 新操作与历史矛盾 | "你上次说这个计划不能降出价（因为新品期需要曝光）。现在还在新品期，确定要降吗？" |

### 1.3 与 2.6 的关系

| | 2.6 操作效果追踪 | 3.1 操作历史记忆 |
|------|------|------|
| 时效 | 次日追踪 | 长期记忆 |
| 粒度 | 逐条追踪 | 聚合 + 模式 |
| 触发 | 自动（早安）/ 用户问 | 渗透在所有交互中 |
| 输出 | "昨天调了6个词，5个有效" | "你过去3个月对这个词调过4次，最佳幅度是15-20%" |

两者共用同一份操作日志。2.6 负责短期追踪，3.1 负责长期记忆。

## 三、代码层：历史记忆

### 3.1 记忆存储

在操作日志基础上扩展记忆字段：

```json
{
  "operation_id": "opt-20260526-003",
  "type": "bid_decrease",
  "scope": {"plan": "618大促", "keyword": "连衣裙"},
  "change": {"before": 3.50, "after": 2.80},
  "context": {
    "reason": "ROI低于1.5",
    "roi_before": 1.2,
    "spend_7d": 5200
  },
  "outcome": {
    "roi_after_3d": 1.8,
    "roi_after_7d": 2.1,
    "result": "effective"
  }
}
```

### 3.2 历史检索规则

用户当前操作/提问触发时，检索相关历史：

| 当前场景 | 检索范围 | 排序权重 |
|---------|---------|---------|
| 操作同一个关键词 | 该词所有历史操作 | 时间×0.5 + 效果×0.5 |
| 操作同一个计划 | 该计划下所有操作 | 时间×0.6 + 相关度×0.4 |
| 问优化建议 | 所有历史有效操作 | 效果×0.7 + 相似度×0.3 |
| 要执行操作 | 同类操作历史结果 | 相似度×0.8 + 时效×0.2 |

### 3.3 模式提取

每天汇总时，代码自动提取：

| 模式 | 计算方式 | 示例 |
|------|---------|------|
| 最佳操作幅度 | 同对象历史操作中，结果="有效"的幅度中位数 | "连衣裙 最佳降幅 15-20%" |
| 重复操作频率 | 同对象 N 天内操作次数 | "这个词过去30天调了6次" |
| 操作偏好时间 | 操作时间分布 | "你通常在周一上午和周四下午调预算" |
| 矛盾操作标记 | 同一对象短期内方向相反的操作 | "先降后涨，可能是试探" |

### 3.4 什么情况下引用历史

| 条件 | 行为 |
|------|------|
| 当前操作对象有 ≥ 2 条历史记录 | 在预览/确认时展示历史摘要 |
| 当前场景与历史场景相似度 > 70% | 主动引用，"上次类似情况..." |
| 当前操作与历史矛盾 | 提醒，"你上次说过..." |
| 历史操作距今 > 90 天 | 标注"较久远"，降低权重 |

## 四、大模型层：记忆融入对话

### 4.1 操作预览时

```
▸ 你准备把「连衣裙」从 ¥3.50 降到 ¥2.80（降20%）

📜 这个关键词的历史：
  05/01 降 20%（¥3.50→¥2.80）→ ROI 1.2→1.8 ✅ 有效
  04/15 降 30%（¥3.50→¥2.45）→ ROI 1.0→1.3 效果一般
  03/20 涨 10%（¥3.00→¥3.30）→ ROI 反降      ❌ 反向

建议：这次降 20% 和上次有效操作一致，可以执行。
```

### 4.2 日常对话中

```
运营："连衣裙 ROI 又掉了"
AIONE："这个词过去3个月你调过4次。降20%那次效果最好（ROI涨50%），
        降30%那次反而不行。要我按20%再来一次吗？"
```

### 4.3 矛盾检测

```
运营："把连衣裙暂停了"
AIONE："你4月说过这个计划是新品期核心词不能停。
        现在还在新品期（上线28天），确定要停吗？"
```

## 3.3 用户偏好学习 — 需求文档

> 日期：2026-05-26 | 类型：执行级需求文档 | 阶段：三
>
> 目标读者：研发团队。AIONE 通过观察运营的日常行为，学习他的关注重点、决策偏好和沟通风格，越用越"懂他"。

---

## 一、功能定义

### 1.1 一句话

AIONE 不问你"你喜欢什么格式"，而是通过观察你的行为自己学——你老看哪个计划、什么指标触发你动手、什么样的预警你会回复。学了之后自动调整自己的行为。

### 1.2 产品形态

不是独立界面，是渗透在所有能力中的自适应层：

| 维度 | 体现 |
|------|------|
| 关注重点 | 你经常查看的计划/品类，自动获得更高优先级 |
| 决策偏好 | 你习惯在什么阈值下动手，自动作为建议基准 |
| 沟通节奏 | 你喜欢简洁还是详细、什么时候不想被打扰 |
| 信任建立 | 你采纳过的建议类型，以后更倾向推荐同类 |

### 1.3 核心原则

> AIONE 不问你，他自己看。你不应该感觉到他在"学习"——你只感觉到他越来越懂你。

---

## 二、学习维度

### 2.1 关注重点

**他观察什么：**

| 信号 | 含义 | 权重变化 |
|------|------|---------|
| 主动查看某计划频次 | 你关心这个计划 | ↑ 优先级 |
| 展开某类数据详情 | 你想看更细的 | ↑ 默认展示粒度 |
| 长时间不查看某计划 | 你不关心 | ↓ 优先级 |
| 反复问同一个指标 | 这是你的核心关注 | ↑ 默认展示位置 |

**效果：**
- 早安中，你关心的计划排前面
- 预警中，你关心的计划阈值更敏感
- 分析中，你关注指标默认展开

### 2.2 决策偏好

**他观察什么：**

| 信号 | 含义 | 自动调整 |
|------|------|---------|
| ROI < X 时你总动手 | 你的容忍线 | 建议阈值 = X |
| 每次降出价都是 15-20% | 你的操作风格 | 默认建议幅度 |
| 你从不暂停主力计划 | 你的底线 | 给主力计划的建议不用"暂停" |
| 新客成本更触动你 | 你在意拉新效率 | 新客指标权重 ↑ |

**效果：**
- 优化建议的阈值贴合你的习惯
- "要不要我帮你调？"的默认幅度是你的常用幅度

### 2.3 沟通节奏

**他观察什么：**

| 信号 | 含义 | 自动调整 |
|------|------|---------|
| "别烦我" / "今天别报了" | 需要安静 | 当日静默 |
| 早上 9:00 你总回复 | 你在 | 早安照常 |
| 中午 12:00 你不回复 | 午休 | 暂缓非紧急推送 |
| 你回复"展开" | 要细节 | 后续默认展示更多细节 |
| 你说"说重点" | 要简洁 | 后续压缩非核心信息 |
| 某个话题你从不回应 | 不感兴趣 | 逐步降低推送权重 |

### 2.4 信任建立

**他观察什么：**

| 信号 | 含义 | 自动调整 |
|------|------|---------|
| 采纳关键词优化建议 | 你认可这类建议 | ↑ 同类建议的推荐优先级 |
| 拒绝预算调整建议 3 次 | 你不认可这类建议 | ↓ 预算类建议的推荐频率 |
| 你说"这个分析不错" | 正面反馈 | ↑ 同类分析风格 |
| 你纠正了 AIONE 的判断 | 需要校准 | 记录纠偏规则 |

## 五、大模型层：偏好应用

### 5.1 早安中

```
无偏好 → 按默认排序展示所有计划
有偏好 → 关注计划前置，忽略计划折叠

"▸ 早安。昨天 ROI 2.35。
  618大促 ROI 3.85 🔥（你最关注的）
  连衣裙拉新花费 ¥6,200（接近你的干预线）
  [测试B已折叠，你不看它]"
```

### 5.2 预警中

```
无偏好 → 默认阈值触发
有偏好 → 按你的容忍线调整

ROI阈值从通用 1.5 → 你的个人阈值 1.3
只有低于 1.3 才预警，因为你通常不关心 1.3 以上的波动
```

### 5.3 建议中

```
无偏好 → 给通用建议
有偏好 → 用你的习惯幅度

"要我帮你把连衣裙降 18% 吗？（你常用的幅度）"
而不是"要我帮你调吗？"（需要你再指定）
```

### 5.4 沟通风格

```
偏好简洁 → 早安 3 段话、预警只报 🔴 级
偏好详细 → 早安 5 段话、预警 🟠 级以上都报
emoji_ok → 用 ▸ · ✅ ⚠️ 等符号
不喜 emoji → 纯文字，顶多用 -
```

## 3.4 周期性记忆 — 需求文档

> 日期：2026-05-26 | 类型：执行级需求文档 | 阶段：三
>
> 目标读者：研发团队。AIONE 识别运营的周期性行为模式——每周一调预算、月底冲量、大促前准备——在周期到来前主动提醒和预备。

---

## 一、功能定义

### 1.1 一句话

AIONE 发现你每周一早上都会调预算、每月最后一周会加投冲量、618 前一个月就开始准备——他记住了这些规律，在周期到来前主动问"要不要提前准备？"

### 1.2 产品形态

不独立推送，在早安和对话中自然融入：

| 场景 | AIONE 行为 |
|------|----------|
| 又到周一 | "新的一周。你通常周一调预算，上周的数据我整理好了，要看看吗？" |
| 月底临近 | "还剩 3 天到月底。过去 3 个月你都在最后一周加了 30% 预算冲量，要提前准备吗？" |
| 大促前 | "距 618 还有 2 周。去年你提前 10 天开始加预算，现在开始吗？" |
| 季度末 | "Q2 快结束了。上季度末你把 ROI < 1 的计划全清了一遍，要我帮你再过一遍吗？" |

## 四、代码层：周期检测

### 4.1 周期性得分

```
对于每个「操作类型 × 时间维度」组合：

每周周期得分 = 
  + 同一星期几重复 3+ 次 → 基础分 30
  + 连续 4+ 周重复 → +30
  + 操作幅度稳定（方差 < 20%）→ +20
  + 时间窗口集中（2小时内）→ +20

得分 ≥ 60 → 标记为周期模式
```

### 4.2 检测窗口

| 周期类型 | 检测窗口 | 最小重复次数 |
|---------|---------|:--:|
| 每周 | 最近 12 周 | 4 次 |
| 每月 | 最近 6 个月 | 3 次 |
| 每季 | 最近 4 个季度 | 2 次 |
| 大促 | 固定日期（618/双11/年货节） | 1 次（手动预设） |

## 3.6 跨店铺品线对比 — 需求文档

> 日期：2026-05-26 | 类型：执行级需求文档 | 阶段：三（提前设计）
>
> 目标读者：研发团队。运营需要横向对比不同店铺/品线的投放表现，同时做同比分析，按货品阶段和渠道维度拆解。AIONE 已支持多店铺数据获取。

---

## 一、功能定义

### 1.1 一句话

运营选择两个店铺/品线，AIONE 拉取双方数据，做横向对比 + 自身同比，按货品阶段 × 渠道交叉分析，高亮差异、识别机会。

### 1.2 典型场景

```
运营："对比一下紫曜单店和 a2 海外紫曜品线 5 月的投放效果"
运营："紫曜 vs a2海外，近30天 ROI、新客成本、新客占比，分阶段分渠道"
运营："紫曜今年 5 月 vs 去年 5 月，ROI 和新客成本变化"
```

### 1.3 核心指标

| 指标 | 横向对比含义 | 同比含义 |
|------|------------|---------|
| ROI | 谁效率更高 | 效率在变好还是变差 |
| 新客成本 | 谁拉新更便宜 | 拉新成本趋势 |
| 花费 | 谁投放量更大 | 预算策略变化 |
| 新客占比 | 谁更偏拉新 | 拉新 vs 存量结构变化 |

### 1.4 分析维度

**货品阶段（产品生命周期）：**

| 阶段 | 特征 | 关注指标 |
|------|------|---------|
| 新品期 | 上线 0-30 天 | CTR、新客占比（拉新为主） |
| 成长期 | 上线 30-90 天 | ROI 增长趋势、新客成本 |
| 成熟期 | 上线 90-180 天 | ROI 稳定性、老客复购 |
| 清仓期 | 促销/下架前 | 花费效率、库存消化 |

**渠道：**

| 渠道 | 说明 |
|------|------|
| 搜索 | 关键词/搜索广告 |
| 推荐 | 猜你喜欢/推荐流 |
| 内容 | 短视频/直播/图文 |
| 直播 | 直播间投放 |

交叉分析 = 货品阶段 × 渠道，如：成长期 × 搜索、成熟期 × 内容。

## 三、代码层：数据计算

### 3.1 数据拉取

```
输入：
  · store_1_id, store_2_id
  · date_range：对比时间段
  · yoy_date_range：同比时间段（自动减365天，或用户指定）
  · dimensions：['product_stage', 'channel']

拉取：
  · 每个店铺的总计：
      ROI, 新客成本, 花费, 新客占比
  · 每个店铺按货品阶段切分：
      新品期 / 成长期 / 成熟期 / 清仓期
      各阶段的 ROI, 新客成本, 花费, 新客占比
  · 每个店铺按渠道切分：
      搜索 / 推荐 / 内容 / 直播
      各渠道的 ROI, 新客成本, 花费, 新客占比
```

### 3.2 对比计算

#### 横向对比

```
横向差异 = store_1 值 - store_2 值
横向差异% = (store_1 - store_2) / store_2 × 100%
```

| 差异% | 显著性 | 标记 |
|:--:|:--:|:--:|
| > 30% | 显著差异 | 🔴 |
| 15-30% | 明显差异 | 🟠 |
| 5-15% | 有差异 | 🟡 |
| < 5% | 无显著差异 | — |

#### 同比对比

```
同比变化 = 今年值 - 去年同期值
同比变化% = (今年 - 去年) / 去年 × 100%
```

判定逻辑同横向对比。

## 五、货品阶段判定规则

货品阶段如何确定？依赖数据源中是否包含 `listing_date`（上架日期）字段：

```
days_since_listing = today - listing_date

≤ 30天   → 新品期
31-90天  → 成长期
91-180天 → 成熟期
> 180天  → 清仓期 / 稳定期
```

如果数据源不包含上架日期，则根据计划名称关键词匹配：
- 含"新品/新款/首发" → 新品期
- 含"主推/爆款" → 成长期/成熟期
- 含"清仓/特卖/尾货" → 清仓期
- 含"拉新" → 成长期

```
Step 4: 生成报告（大模型）
  按 需求文档 4.1 模板输出：
  · 总体对比表
  · 货品阶段对比
  · 渠道对比
  · 同比分析（如有）
  · 机会识别
```

## 关键规则

### 店铺/品线不存在时

AIONE 已支持多店铺数据。如果用户指定的店铺/品线不存在或未接入：
→ "我没有找到「XX」的数据。当前已接入的店铺有：紫曜、a2海外。需要接入新店铺吗？"

### 数据不完整时

| 情况 | 处理 |
|------|------|
| 某店铺缺新客维度 | 仅对比 ROI+花费，标注"新客数据不可用" |
| 某店铺缺渠道拆分 | 仅对比总计+货品阶段，标记"渠道拆分不可用" |
| 同比数据缺失 | 仅做横向对比，标注"历史数据不可用，仅横向对比" |
| 某货品阶段无数据 | 该阶段显示"无投放"，不参与差异计算 |

### 货品阶段判定

```
如果有 listing_date（上架日期）：
  ≤30天 → 新品期 / 31-90天 → 成长期
  91-180天 → 成熟期 / >180天 → 清仓期

如果无 listing_date，按计划名称关键词：
  含"新品/新款/首发" → 新品期
  含"主推/爆款" → 成长期/成熟期
  含"清仓/特卖/尾货" → 清仓期
  含"拉新" → 成长期
  默认 → 成熟期
```

### 渠道拆分

如果数据源不支持按渠道拆分：
→ 跳过渠道对比，仅做总览 + 货品阶段
→ 标注"渠道拆分需数据源支持"

### 差异解读原则

- 差异 > 30% 且对某方不利 → 不是"A比B差"，而是"B有优化空间"
- 某方全面落后 → 寻找领先维度，给出"亮点"
- 双方各有优势 → 标注"互补"关系

## 输出示例

```
▸ 紫曜单店 vs a2海外紫曜品线 · 5月对比

📊 总体：
                    紫曜      a2       差异
  ROI               2.35     1.80      +30.6% 🔴
  新客成本           ¥52      ¥78       -33.3% 🟢
  花费              28,500   15,200     +87.5% 🔴
  新客占比           42%      55%       -23.6% 🟠

📂 按货品阶段：
  新品期 — 紫曜 ROI 1.2 / a2 0.8 → 紫曜冷启动更高效
  成长期 — 紫曜 ROI 2.5 / a2 1.9 → 差距缩小但仍领先
  成熟期 — 双方接近（2.8 vs 2.6）
  清仓期 — a2 反而领先 → 清仓策略值得借鉴

📡 按渠道：
  搜索 — 紫曜大幅领先（ROI 2.8 vs 1.5）→ a2 搜索是优化重点
  内容 — a2 领先（2.1 vs 1.6）→ a2 内容种草更强
  直播 — 持平

⏰ 同比：
  紫曜 ROI 同比 -12%，新客成本 +18% → 竞争加剧
  a2 ROI 同比 +5% → 稳步成长

💡 机会：
  · a2 搜索渠道 ROI 仅 1.5，优化空间大
  · 紫曜可以参考 a2 的清仓策略
  · a2 内容投放效率高，可加大内容预算
```
