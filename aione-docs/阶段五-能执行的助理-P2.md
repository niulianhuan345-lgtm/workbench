## 1. 概述

### 1.1 模块定位

人群策略执行是AIONE操作层的核心能力之一。它将"人群洞察"和"人群创建"的结果落实到具体的推广计划中，完成从"分析→创建→应用"的闭环。用户通过自然语言指令，即可将人群包绑定到指定计划，AIONE会自动理解场景语义、检测冲突、展示影响评估，并在确认后通过API写入万相台无界。

### 1.2 核心价值

- **降门槛**：用户不需要理解"定向包ID""人群包编号"等底层概念，用业务语言即可操作
- **防误操作**：自动检测全站推广互斥、人群包状态异常、覆盖人数过大/过小等风险
- **策略感知**：理解用户所在场景（新品/拉新/复购/大促），自动推荐合适的人群组合
- **效果可解释**：用DEEPLINK视角解释操作效果，"这个操作会把约12万人从Discover推到Engage"

### 1.3 与上下游的关系

```
人群创建(5.3) → 人群策略执行(5.4) → 计划管理(5.x)
                      ↓
               策略模板跟投(5.5) — 批量应用场景
               全站推广操控(5.6) — 互斥检测
```

## 2. 功能需求

### 2.1 核心场景

| 场景编号 | 场景名称 | 用户意图 | 典型话术 |
|---------|---------|---------|---------|
| S5.4.1 | 人群包绑定 | 将已有人群包应用到计划 | "把刚建的人群包加到618计划" |
| S5.4.2 | 人群包替换 | 替换计划中的现有人群定向 | "给拉新计划换上竞品人群" |
| S5.4.3 | 批量追加 | 多个计划统一添加人群 | "所有计划统一加上会员人群" |
| S5.4.4 | Lookalike扩展 | 基于现有人群做相似扩展 | "给这个计划加Lookalike扩展人群" |
| S5.4.5 | 人群策略推荐 | 根据场景自动推荐人群组合 | "新品冷启动应该用什么人群？" |

### 2.2 功能详细说明

#### 2.2.1 人群包绑定（S5.4.1）

**输入**：人群包名称/ID + 目标计划名称/ID
**输出**：绑定结果确认 + 操作日志

**执行步骤**：
1. 解析用户指令，提取人群包和目标计划
2. 校验人群包状态（可用/生成中/已过期/覆盖为0）
3. 校验计划状态（投放中/暂停/已结束）及互斥规则
4. 展示覆盖人数预估
5. 展示DEEPLINK影响评估
6. 用户确认后执行写入

#### 2.2.2 人群包替换（S5.4.2）

与绑定的区别在于需要先"解绑旧人群"。AIONE需要：
- 识别计划当前绑定的人群包
- 展示替换前后对比（覆盖人数变化、DEEPLINK阶段偏移）
- 支持预览模式：展示替换效果但不执行

#### 2.2.3 批量追加（S5.4.3）

- 支持按计划标签批量选择（"所有拉新计划""大促计划组"）
- 支持按计划状态过滤（"只在投放中的计划上加"）
- 批量操作的进度追踪和失败回滚

#### 2.2.4 Lookalike扩展（S5.4.4）

- 基于选定种子人群生成相似人群
- 支持扩展倍数：1.5倍/2倍/3倍
- 展示扩展后覆盖人数变化

#### 2.2.5 人群策略推荐（S5.4.5）

AIONE根据上下文场景自动推荐人群组合。场景识别规则：

| 场景关键词 | 推荐人群组合 | 说明 |
|-----------|------------|------|
| 新品/冷启动/测款 | 类目兴趣人群 + 相似宝贝人群 | 行业经验：新品冷启最优 |
| 拉新/抢新客/拓新 | 竞品人群 + 跨类目兴趣人群 | 覆盖竞品流失用户 |
| 复购/老客/回购 | 180天购买人群 + 会员人群 | 优先触达高价值老客 |
| 大促/618/双11/蓄水 | 浏览未购 + 加购未购 + 兴趣人群 | 蓄水期扩大触达 |
| 大促/收割/爆发 | 近15天互动人群 + 购物车人群 | 收割期精准转化 |
| 清仓/甩货 | 价格敏感人群 + 历史浏览人群 | 低成本清库存 |
| 竞品截流 | 竞品搜索人群 + 竞品购买人群 | 截取竞品流量 |

### 2.3 冲突检测规则

| 冲突类型 | 检测条件 | 处理方式 |
|---------|---------|---------|
| 全站推广互斥 | 目标计划中的商品已开启全站推广 | 阻止操作，提示"该商品已开启全站推广，不能设置其他人群定向" |
| 人群包过期 | 人群包状态为"已过期" | 警告，建议重新生成或换用其他人群包 |
| 覆盖人数为0 | 人群包预估覆盖为0 | 警告，可能因标签过滤条件过严 |
| 覆盖人数过大 | 人群包覆盖 > 1000万 | 提示，建议缩小范围避免预算浪费 |
| 重复绑定 | 目标计划已绑定该人群包 | 提示"已绑定，无需重复操作" |

### 2.4 DEEPLINK影响评估

每次人群策略执行时，AIONE需要展示DEEPLINK视角的影响分析：

```
┌─────────────────────────────────────────────────┐
│  DEEPLINK 影响评估                               │
│                                                 │
│  Discover ─→ Engage ─→ Interest ─→ Action ─→ Loyal │
│     ↑          ↑                              │
│  当前状态   本次操作将把约12万人从Discover推到Engage   │
│                                                 │
│  操作后预估覆盖：35万人                           │
│  操作前覆盖：23万人                               │
│  D→E 增量：+12万人                               │
└─────────────────────────────────────────────────┘
```

## 5. 非功能需求

### 5.1 性能指标
- 单次绑定操作响应时间：< 3秒
- 批量绑定（≤50个计划）：< 30秒
- 覆盖人数预估：实时返回（使用人群包生成时缓存的最新数据）

### 5.2 安全要求
- 所有写入操作需要二次确认
- 批量操作支持部分回滚
- 操作日志保留90天，可追溯

### 5.3 容错处理
- API调用失败：自动重试3次，间隔1/3/5秒
- 部分计划失败：展示成功/失败明细，支持一键重试失败项
- 网络超时：展示操作状态为"处理中"，异步轮询结果

  ├─ 步骤5：方案展示与确认

  └─ 步骤6：执行写入
       ├─ 调用API绑定人群
       ├─ 展示执行结果（成功/失败明细）
       └─ 更新操作日志
```

## 3. 关键规则

### 3.1 全站推广互斥规则（最高优先级）

> **规则**：同一商品开启全站推广后，不能通过其他计划设置人群定向。

检查逻辑：
1. 获取目标计划中的所有商品ID
2. 查询每个商品的全站推广状态
3. 若任意商品已开启全站推广 → 提示用户，提供"跳过该商品"或"取消操作"选项

提示模板：
```
⚠️ 检测到以下商品已开启全站推广，不支持人群定向调整：
  - 爆款A（商品ID：123456）
  - 热销款B（商品ID：789012）

请选择：
  1. 跳过这些商品，仅对其他商品生效
  2. 取消本次操作
```

### 3.2 人群包状态校验

| 状态 | 处理 |
|------|------|
| 可用（已生成） | 正常执行 |
| 生成中 | 提示等待，提供"生成完成后自动绑定"选项 |
| 已过期 | 阻止操作，建议重新生成 |
| 覆盖为0 | 警告，建议检查标签条件 |

### 3.3 DEEPLINK评估算法

```
评估逻辑（简化版）：
1. 获取人群包中各DEEPLINK阶段的人数分布
2. 当前计划覆盖：取交集计算

4. 增量 = 新覆盖 - 当前覆盖
5. 展示各阶段增量

D(Discover)→E(Engage)→I(Interest)→A(Action)→L(Loyal)→S(Share)→R(Retention)

## 1. 概述

### 1.1 模块定位

策略模版跟投是AIONE的纯Skill层能力。它让用户通过"跟投蛋蛋的小蛮腰打爆策略"这样的自然语言指令，快速复刻讲师/达人的成功投放策略。AIONE负责理解用户的模糊引用、匹配对应的策略模版、结构化展示策略组成、确认后生成操作方案。这是一个"零门槛策略复制"的能力。

### 1.2 核心价值

- **知识普惠**：将头部讲师的成功策略沉淀为可复用的模版，普通商家一键跟投
- **模糊匹配**：用户不需要记住精确的策略名称，"小蛮腰""蛋蛋那套"都能被理解
- **风险可控**：自动适配用户的预算和ROI目标，不会照搬不适合的策略
- **灵活跟投**：支持全量跟投和部分跟投（"只要第一个和第三个"）

### 1.3 与上下游关系

```
策略模版库(静态) → 策略模版跟投(5.5) → 计划创建
                         ↓
               人群策略执行(5.4) — 人群包匹配
               全站推广操控(5.6) — 计划配置
```

```

适配后每个计划预算 = P_template_plan × (P_user / P_template)

最小预算阈值：每个计划不低于100元/日
最大预算阈值：每个计划不高于用户账户余额/剩余天数
```

### 4.2 ROI目标适配算法

```
用户ROI R_user，模版ROI R_template

偏移量 = R_user - R_template_mid（取模版中位数ROI）
适配后每个计划ROI = 原ROI + 偏移量

约束：ROI不低于0.5，不高于10.0
```

### 4.3 商品填充规则

- 若用户指定了商品 → 使用指定商品
- 若用户未指定商品 → 使用店铺"近7天销量TOP3"商品
- 单品模式计划 → 使用TOP1商品
- 全店模式计划 → 覆盖全部在售商品

## 4. 参数适配算法

### 4.1 预算适配

```
输入：用户日预算 B_user，模版总预算 B_template
输出：每个计划的日预算

步骤：
1. 计算缩放比 scale = B_user / B_template
2. 对于每个计划 i：
   预算_i = max(100, plan_i.原预算 × scale)
3. 若存在多个计划，微调使总和 = B_user（按比例分配余数）
```

### 4.2 ROI目标适配

```
输入：用户ROI目标 R_user，模版各计划ROI [r1, r2, ..., rn]
输出：适配后各计划ROI

步骤：
1. 计算模版ROI中位数 r_mid
2. 计算偏移量 offset = R_user - r_mid
3. 对于每个计划 i：
   roi_i = clamp(ri + offset, 0.5, 10.0)
```

### 4.3 商品选择

```
优先级：
1. 用户明确指定的商品ID
2. 用户指定的筛选条件（"销量最高的3个"）
3. 默认：店铺近7天销量TOP3商品（单品模式用TOP1）
```

## 1. 概述

### 1.1 模块定位

全站推广操控是AIONE操作层中针对万相台无界"全站推广"产品的专属控制能力。全站推广是无界体系中最强力的投放产品——AI效果智达（ROI达标率+10%）、全店模式（一键托管GMV+31%）、一键起量（放量+40%）、平台推荐品（GMV+35.6%）——但它有严格的互斥规则和模式切换影响。AIONE需要让用户安全、便捷地操控全站推广。

### 1.2 核心价值

- **安全操控**：自动检测互斥冲突，防止误操作导致计划冲突
- **后果透明**：模式切换前说明影响范围，让用户在知情状态下决策
- **效果预估**：调整ROI目标或起量时展示效果预估
- **一键直达**：自然语言即可完成启停/调ROI/起量/切换模式

### 1.3 全站推广三种模式概述

| 模式 | 说明 | 适用场景 |
|------|------|---------|
| 单品模式 | 针对单个商品的全站流量投放 | 爆款打爆、单品冲量 |
| 全店模式 | 一键托管全店所有在售商品 | 全店动销、托管运营 |
| 分组投放 | 按商品分组分别设置策略 | 多品类差异化运营 |

---

## 2. 核心规则（必须严格遵守）

### 2.1 互斥规则（最高优先级）

> ⚠️ **规则A**：同一商品开启全站推广后，不能通过其他计划对该商品进行任何投放。
> ⚠️ **规则B**：切换到全店模式后，全店所有商品都将被全站推广覆盖，此时不能为任何商品创建其他计划。

### 2.2 模式切换规则

| 切换方向 | 后果说明 | 是否可逆 |
|---------|---------|---------|
| 单品模式 → 全店模式 | 全店所有在售商品纳入全站推广，其他计划中的这些商品将被暂停 | 可切回，但暂停的计划需手动恢复 |
| 全店模式 → 单品模式 | 仅保留当前选中的商品在全站推广中，其他商品的计划可恢复 | 是 |
| 单品模式 → 分组投放 | 按商品分组拆分为多个策略 | 是 |

### 2.3 一键起量规则

- 一键起量有预算上限（通常为日预算的50%）
- 一键起量持续时间默认24小时，可手动停止
- 一键起量期间ROI可能下降（放量优先于ROI控制）
- 同一商品30天内只能使用3次一键起量

### 2.4 ROI调整规则

- ROI目标调高 → 系统收紧出价，曝光量可能下降，转化率可能提升
- ROI目标调低 → 系统放宽出价，曝光量上升，转化率可能下降
- ROI调整后建议观察至少24小时再评估效果
- 全店模式下的ROI是所有商品的平均ROI目标

## 5.7 批量操作引擎 — 需求文档

## 1. 概述

### 1.1 能力定位
批量操作引擎是AIONE「能执行的助理」阶段的核心能力之一，赋予AI Agent对广告计划进行批量操作的能力，包括批量暂停、启用、修改出价、调整预算等。用户通过自然语言描述操作范围和条件，Agent自动解析、预览、确认并执行。

### 1.2 核心价值
- **效率提升**：一次对话完成原本需要逐个点击数十个计划的操作
- **降低出错**：条件筛选替代手工勾选，避免遗漏或误操作
- **可预期性**：执行前预览受影响范围，用户确认后再操作
- **定时自动化**：支持定时条件触发，实现"设置一次，持续生效"

### 1.3 与现有能力的关系
- 依赖 **2.1 计划查询与筛选** 进行范围提取
- 依赖 **2.6 操作效果追踪** 记录操作日志
- 与 **5.8 大促模式管理** 协同：大促模式底层调用批量操作引擎

## 2. 用户故事

### US-1：条件筛选批量暂停

- 超过10个计划时弹出二次确认
- 执行后每个计划状态变更成功，并汇总报告

### US-2：批量修改出价
> 作为投手，在大促期间我想"把所有618相关的计划出价提高20%"，系统自动识别618相关计划并批量调整。

**验收标准：**
- 系统正确识别"618相关"计划（计划名含618/大促等关键词）

- 支持百分比和绝对值两种调整方式

### US-3：批量调整预算

**验收标准：**
- 正确筛选日预算<300的计划
- 预览展示预算变更对比
- 支持"提到X元"和"翻倍/增加X%"两种语义

### US-4：定时批量操作
> 作为投手，我想"每天晚上12点自动暂停所有计划"，实现定时自动管控。

**验收标准：**

# 批量操作引擎 Skill

## 核心工作流

```
1. 意图解析
   ├── 识别操作类型：暂停/启用/改出价/改预算
   ├── 提取筛选条件：ROI/花费/转化/计划名/时间/出价/预算/状态
   └── 判断是否定时：时间词 → 走定时分支

2. 范围查询
   ├── 调用计划查询能力获取符合条件的计划列表
   ├── 若无匹配 → 提示"未找到符合条件的计划"，建议放宽条件
   └── 若有匹配 → 进入预览

3. 预览确认
   ├── 展示受影响计划清单（表格形式）
   ├── 展示操作前后对比
   ├── 展示影响预估（金额变化）
   ├── >10个计划 → 二次确认
   └── 预算变更>2倍 → 高亮提醒

4. 执行
   ├── 逐项调用操作API
   ├── 分批执行（每批最多10个，避免超时）
   ├── 实时进度反馈（X/N）
   └── 失败项自动重试3次

5. 结果反馈
   ├── 成功/失败汇总
   ├── 失败明细（如有）
   ├── 回滚入口（5分钟内）
   └── 写入操作追踪日志

6. 定时分支（可选）
   ├── 解析时间规则（每天/每周/指定时间）
   ├── 创建定时任务记录
   ├── 设置执行前提醒（提前5分钟）
   └── 返回任务ID和管理入口
```

## 关键规则

### 规则1：操作类型识别
| 用户表述 | 操作类型 | 参数提取 |
|---------|---------|---------|
| "暂停/停了/关掉" | 暂停 | - |
| "开启/启用/重新投放" | 启用 | - |
| "出价改/调整/降/提高 X%/X元" | 改出价 | 百分比或绝对值 |
| "预算改/翻倍/提到/调整" | 改预算 | 固定值或百分比 |

### 规则2：筛选条件识别
- ROI：`ROI低于X` / `投产比不到X` / `ROI大于X`
- 花费：`花费超过X` / `消耗大于X` / `花了X以上`
- 转化：`没有转化` / `转化少于X` / `没出单`
- 计划名：`XX相关的` / `名字带XX的` → 模糊匹配
- 时间：`上周`（7天）/ `近3天` / `本月` / `今天`
- 场景：`关键词场景` / `精准人群场景` 等
- 预算：`日预算低于/高于X`
- 出价：`出价高于/低于X`
- 复合条件：`但/且` → AND / `或` → OR

### 规则3：安全机制
- 所有批量操作必须有预览步骤
- 影响计划数 > 10：二次确认，要求用户明确回复
- 预算/出价变更幅度提示：超过50%高亮提醒
- 执行前锁定检查：计划是否已在执行中被修改

### 规则4：定时任务
- 时间格式解析：`每天晚上X点` / `每周X X点` / `每天上午/下午X点`
- 定时任务独立存储，可查询/修改/取消
- 触发前5分钟推送提醒
- 触发时重新评估条件（条件可能已变化）

### 规则5：错误处理
- 部分失败不中断整体流程
- 失败项详细记录原因（权限不足/计划已删除/参数超限）
- 提供"重试失败项"入口
- API限流时自动降速（间隔200ms→500ms→1s）

## 5.8 大促模式管理 — 需求文档

## 1. 概述

### 1.1 能力定位
大促模式管理是AIONE为电商大促场景（618、双11、双12、年货节等）设计的专项能力。系统内置四阶段策略模型，用户一键即可将全部广告计划切换至对应大促阶段模式，Agent自动调整出价、预算、人群等参数。大促结束后可一键恢复日常模式。

### 1.2 核心价值
- **策略专业化**：内置经过验证的四阶段投放策略，降低大促投放门槛
- **一键切换**：一次对话完成数十个计划的参数调整，告别手工逐项修改
- **阶段可视化**：大促日历清晰展示各阶段时间线和关键动作
- **安全回滚**：随时可回退到切换前的参数配置

### 1.3 与现有能力的关系
- 底层调用 **5.7 批量操作引擎** 执行参数批量调整
- 依赖 **2.6 操作效果追踪** 记录阶段切换历史
- 与 **2.5 智能预算重分配** 协同优化大促预算
- 与 **3.5 人群包创建** 协同调整人群定向

---

## 2. 四阶段策略模型

### 2.1 蓄水期（大促前 7-14 天）

**目标：** 拉新种草，积累人群资产

| 调整项 | 策略 | 参数建议 |
|-------|------|---------|
| 拉新预算 | 增加 30%-50% | 原预算 × 1.3-1.5 |
| 素材策略 | 增加测款计划 | 创建新素材测试计划 |
| 人群定向 | 放宽定向条件 | 兴趣标签放宽一级 |
| 出价策略 | 适度提高10%-20% | 抢占流量 |
| 关键词 | 增加品类词、场景词 | 拓展关键词覆盖面 |

### 2.2 预热期（大促前 1-3 天）

**目标：** 强曝光，收藏加购

| 调整项 | 策略 | 参数建议 |
|-------|------|---------|
| 曝光预算 | 增加 50%-100% | 原预算 × 1.5-2.0 |
| 一键起量 | 开启快速起量 | 加速冷启动 |
| 人群策略 | 加购人群重定向 | 启用加购/收藏人群包 |
| 出价策略 | 提高20%-30% | 确保曝光竞争力 |
| 素材 | 突出大促利益点 | "满300减50"等 |

### 2.3 爆发期（大促当天）

**目标：** 最大化成交

| 调整项 | 策略 | 参数建议 |
|-------|------|---------|
| 预算 | 最大化/不设上限 | 原预算 × 3-5 |
| 投放模式 | 全店/智能投放 | 最大化覆盖 |
| ROI目标 | 适度放宽 | 原ROI × 0.7-0.8 |
| 出价策略 | 实时竞价最大化 | 系统自动竞价 |
| 时段 | 全天候投放 | 0:00-24:00 |

### 2.4 返场期（大促后 1-3 天）

**目标：** 触达未成交用户，平稳回落

| 调整项 | 策略 | 参数建议 |
|-------|------|---------|
| 预算 | 逐步回落 | Day1: 原预算×2, Day2: ×1.5, Day3: 恢复 |
| 人群策略 | 触达浏览未购/加购未购 | 启用召回人群包 |
| 素材 | 返场/最后机会 | "大促返场 最后3天" |
| 出价策略 | 逐步恢复 | 每天降低10%-15% |
| 新计划 | 逐步暂停 | 测款计划可选择性保留 |

## 5. 异常处理

| 异常场景 | 处理方式 |

| 用户中途取消 | 已执行的部分不回滚，未执行的取消 |

## 6. 非功能需求

- **切换响应**：阶段切换方案生成 < 5秒
- **执行时间**：批量调整执行 < 30秒（50个计划以内）
- **快照存储**：保留最近10次阶段切换快照
- **日历精度**：大促日历支持到小时级别
- **数据安全**：切换前参数快照加密存储

### 规则2：四阶段策略参数默认值

**蓄水期：**
- 预算：+30%~50%
- 出价：+10%~20%
- 人群：定向放宽一级
- 关键词：拓展品类词
- 素材：新建测款计划
- 一键起量：可选开启

**预热期：**
- 预算：+50%~100%
- 出价：+20%~30%
- 人群：启用加购/收藏重定向
- 素材：应用大促素材
- 一键起量：开启
- ROI目标：维持

**爆发期：**
- 预算：最大化（建议设上限）
- 投放模式：全店智能
- 出价：系统自动竞价
- ROI目标：放宽至日常70%
- 时段：全天候
- 一键起量：全开

**返场期：**
- 预算：逐步回落（D1×2, D2×1.5, D3恢复）
- 人群：召回人群包（浏览未购/加购未购）
- 素材：返场素材
- 出价：每天降10%-15%
- 测款计划：选择性暂停

### 规则3：安全机制
- 切换前必须生成完整预览
- 预算增幅超过100%时高亮提示
- 爆发期必须提示设置花费上限
- 每次切换自动保存快照，用于回滚
- 不支持跨阶段跳跃切换（如从蓄水直跳爆发，需逐阶段切换）

### 规则4：自定义策略
- 用户可覆盖任意阶段的任意参数
- 自定义参数按用户级别存储（不影响默认模板）
- 支持"只看预算"/"出价不动"等部分调整指令
- 自定义策略可保存为个人模板，下次复用

### 规则5：回滚规则
- 保留最近10次阶段切换快照
- 回滚时展示变更预览
- 回滚同样需要用户确认
- 快照包含：时间戳、阶段、所有计划参数
