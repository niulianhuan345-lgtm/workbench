## 4.1 反馈学习 — 需求文档

> 日期：2026-05-26 | 类型：执行级需求文档 | 阶段：四
>
> 目标读者：研发团队。运营对AIONE的建议给出显式反馈（好/不好/为什么），AIONE用反馈持续校准自己的推荐策略。

---

## 一、功能定义

### 1.1 一句话

运营告诉 AIONE"这个建议不错"或"不对，应该这样"，AIONE 用这些反馈持续修正自己的判断逻辑，同样的错不犯第二次。

### 1.2 与 3.3 的区别

| | 3.3 用户偏好学习 | 4.1 反馈学习 |
|------|------|------|
| 学习方式 | 隐式（观察行为） | 显式（运营主动反馈） |
| 速度 | 慢（需多天积累） | 快（一次反馈即生效） |
| 精度 | 模糊（推断） | 精确（运营说的） |
| 示例 | "你总在ROI<1.3时动手" | "你上次说这个建议不对，原因是..." |

### 1.3 产品形态

在任何 AIONE 给出建议/分析后，运营可以自然反馈：

```
AIONE："建议把连衣裙降20%"
运营："不对，连衣裙是新品期不能降"    ← 负反馈 + 原因
AIONE："明白了，新品期不降出价。我记下了。"

AIONE："建议暂停测试B"
运营："好，暂停"                      ← 正反馈
AIONE："收到。以后类似低效测试计划我会优先建议暂停。"
```

---

## 二、反馈类型

### 2.1 正反馈

| 运营说 | AIONE学到 |
|--------|---------|
| "这个建议不错" / "好" / "执行" | 这类建议方向是对的，加大推荐权重 |
| "分析很准" | 分析方法和结论可信，增加置信度 |
| "就按你说的来" | 操作幅度合适，记录为参考基准 |

### 2.2 负反馈

| 运营说 | AIONE学到 |
|--------|---------|
| "不对" / "不行" | 这个方向不对，降低同类推荐权重 |
| "这个计划不能降（因为新品期）" | 记录规则：新品期计划不推荐降出价 |
| "幅度太大了" | 记录偏好：降幅不超过 X% |
| "不用管这个" | 标记对象为低优先级，减少推送 |

### 2.3 修正反馈

| 运营说 | AIONE学到 |
|--------|---------|
| "不是降连衣裙，是降夏季女装" | 对象识别纠偏 |
| "应该降 10% 不是 20%" | 幅度纠偏 |
| "等大促结束再说" | 时机纠偏，记录条件 |

## 四、代码层：规则管理

### 4.1 反馈解析

大模型从运营的自然语言中提取结构化反馈：

```json
{
  "feedback_type": "negative",
  "context": {
    "skill": "2.4",
    "suggestion": "降出价20%",
    "target": {"plan": "连衣裙拉新", "keyword": "连衣裙"}
  },
  "reason": "新品期不能降出价",
  "new_rule": {
    "type": "scope_restriction",
    "scope": "plan_lifecycle",
    "condition": "lifecycle == '新品期'",
    "action": "block_bid_decrease"
  }
}
```

### 4.2 规则类型

| 规则类型 | 来源 | 作用 |
|---------|------|------|
| 权重调整 | 正/负反馈 | 调高/调低某类建议的推荐优先级 |
| 范围限制 | 负反馈（含原因） | 特定条件下禁止某类建议 |
| 参数校准 | 修正反馈 | 调整默认幅度/阈值 |
| 对象忽略 | "不用管这个" | 标记对象不推送 |

### 4.3 规则生命周期

```
新增规则 → 立即生效
        → 7天内同类建议被触发但运营没再反对 → 规则确认
        → 运营主动说"这个规则撤销" → 规则失效
        → 90天未触发 → 规则休眠（仍存在但权重降低）
```

## 五、大模型层：反馈融入对话

### 5.1 收到负反馈时

```
运营："不对，连衣裙是新品期不能降"
AIONE："明白了。新品期计划不降出价——我记下了。
        以后连衣裙拉新在30天内我不会建议降出价。"
```

### 5.2 应用规则时

```
（3天后，另一个新品期计划）

AIONE："爆款主推的CPC涨了，建议降10%... 
        等等，爆款主推还在新品期（上线12天），按你之前的规则不降。
        建议先观察，或者调整匹配方式？"
```

### 5.3 主动询问规则

```
（规则闲置30天后再次触发）

AIONE："之前你说新品期不降出价，这个规则还在。但连衣裙拉新已经快过新品期了（上线28天），
        现在要降吗？"
```

## 4.2 操作模式学习 — 需求文档

> 日期：2026-05-26 | 类型：执行级需求文档 | 阶段：四
>
> 目标读者：研发团队。AIONE观察运营的操作序列，学习"先做什么→再做什么→效果好不好"的套路，形成操作模式，自动建议完整流程。

---

## 一、功能定义

### 1.1 一句话

你每次调投放不是"一下调完"，而是有一定套路——先降出价观察两天，有效果再加预算；或者先换素材再调人群。AIONE 学会你的套路后，下次直接建议完整流程："要不要按你的套路来？先降 20% 观察两天，有效果再加预算。"

### 1.2 产品形态

在运营要开始一轮操作时，AIONE 主动问：

| 场景 | AIONE |
|------|------|
| 运营又遇到 ROI 下降 | "你遇到ROI下降的套路是：第1天降出价20%→第3天看效果→好就加预算。要按这个来吗？" |
| 运营要换素材 | "你换素材的套路是：先上新素材→跑3天→保留CTR最高的→停掉差的。这次也要这样吗？" |
| 运营开始大促准备 | "你大促准备的套路：提前2周上新素材→提前1周加预算20%→提前3天全面提价。要按这个节奏走吗？" |

---

## 二、模式识别

### 2.1 什么是操作序列

一系列有时间顺序和因果关系的操作组合：

```
例：ROI下降处理套路
  Day 1: 降出价 20%（2.4 关键词批量优化）
  Day 3: 查看效果（2.6 操作效果追踪）
  效果好→ Day 4: 加预算 15%（2.5 智能预算重分配）
  效果不好→ Day 4: 换素材（平台手动操作）
```

### 2.2 检测规则

```
序列检测条件：
  1. 同一对象（计划/词）
  2. 操作间时间间隔 1-5 天
  3. 操作有因果逻辑（降出价→观察→加预算）
  4. 同一模式重复 3 次以上
  5. 最终效果为正（ROI改善/花费可控）
```

### 2.3 模式库

```json
{
  "patterns": [
    {
      "id": "pat-001",
      "name": "ROI下降处理套路",
      "trigger": "plan ROI下降 > 20%",
      "confidence": 85,
      "observed_count": 5,
      "steps": [
        {"day": 1, "action": "bid_decrease_20pct", "skill": "2.4"},
        {"day": 3, "action": "check_effect", "skill": "2.6"},
        {"day": 4, "action": "budget_increase_15pct", "skill": "2.5", "condition": "roi_improved"}
      ],
      "avg_outcome": "ROI +35%",
      "last_used": "2026-05-15"
    }
  ]
}
```

## 4.3 大促智能管理 — 需求文档

> 日期：2026-05-26 | 类型：执行级需求文档 | 阶段：四
>
> 目标读者：研发团队。618、双11等大促期间的预热→爆发→返场全流程自动化管理，AIONE 按阶段自动调整预算、出价、素材策略。

---

## 一、功能定义

### 1.1 一句话

大促不是一天——是预热期→爆发期→返场期三个阶段的连续战役。AIONE 按预设策略自动推进每个阶段的预算分配、出价调整和素材轮换，运营只需确认关键决策。

### 1.2 大促三阶段

| 阶段 | 时间 | 目标 | 核心策略 |
|------|------|------|---------|
| 预热期 | 前 7-14 天 | 加购收藏蓄水 | 逐步加预算、测试素材、低价引流 |
| 爆发期 | 当天及前后 2 天 | 冲刺转化 | 全量预算、高出价抢量、TOP素材集中 |
| 返场期 | 后 3-7 天 | 余量收割 | 逐步降预算、性价比素材、长尾词收割 |

### 1.3 产品形态

运营在距大促 2 周时告诉 AIONE："准备 618"。

AIONE 自动：
1. 分析去年同大促数据（如果有）
2. 生成分阶段策略方案
3. 运营确认后，按时间线自动推进
4. 每天早安中报告大促进度
5. 异常时主动提醒调整

---

## 二、策略模板

### 2.1 预算策略

| 阶段 | 预算变化 | 触发时间 |
|------|---------|---------|
| 预热 D-14~D-3 | 逐日 +5~10% | 每天 06:00 |
| 爆发 D-2~D+2 | 预算拉满（日常 2-3 倍） | D-2 06:00 |
| 返场 D+3~D+7 | 逐日 -10~15% | 每天 06:00 |

### 2.2 出价策略

| 阶段 | 出价变化 | 原因 |
|------|---------|------|
| 预热期 | 略低于日常（-10%） | 低成本蓄水 |
| 爆发期 | 日常 1.5-2 倍 | 全力抢量 |
| 返场期 | 逐步回落 | 收割长尾 |

### 2.3 素材策略

| 阶段 | 素材策略 |
|------|---------|
| 预热期 | 测试 3-5 套素材，筛选 TOP2 |
| 爆发期 | 主力 TOP2 素材集中投放 |
| 返场期 | 切换返场/清仓主题素材 |

## 六、自主学习：平台动态感知

> 大促策略不是一成不变的。平台每年都会有新活动、新玩法、新工具。AIONE 应该自己去发现这些变化，更新自己的大促策略。

### 6.1 感知什么

| 信息类型 | 来源 | 频率 | 用途 |
|---------|------|:--:|------|

## 四、代码层：策略发现

### 4.1 最佳实践判定

一个策略被判定为"最佳实践"，需满足：

| 条件 | 阈值 |
|------|------|
| 效果持续稳定 | ≥ 7 天 |
| 效果显著优于同类 | ROI > 品类中位数 × 1.3 |
| 花费充足（非偶然） | 累计花费 > ¥500 |
| 运营未标记忽略 | 未被排除 |

### 4.2 复用潜力计算

```
复用潜力 = 策略效果 × (1 - 目标店当前同类策略效果/策略效果)

例：A店关键词 ROI 3.5，B店同品类平均ROI 1.8
     复用潜力 = 3.5 × (1 - 1.8/3.5) = 1.7
     潜力 > 1.0 → 值得推荐
```

## 4.6 策略模拟 — 需求文档

> 日期：2026-05-26 | 类型：执行级需求文档 | 阶段：四
>
> 目标读者：研发团队。运营在做重大调整前，AIONE 基于历史数据和行业基准做沙盘推演："如果这么做，预计 ROI 会怎么变、花费会怎么变、有没有风险。"

---

## 一、功能定义

### 1.1 一句话

"如果我把预算从 A 挪给 B，ROI 会涨还是跌？"——AIONE 不做直觉判断，而是基于历史数据做沙盘推演，告诉你预期结果和置信度。

### 1.2 产品形态

运营用自然语言描述假设场景，AIONE 模拟推演：

```
运营："如果我把618大促的预算从 ¥10,000 降到 ¥7,000，挪给连衣裙拉新，预计效果怎么样？"

AIONE："模拟结果：
       618大促：日花费 ¥7,000 → ROI 预计 3.5-3.8（历史数据显示预算降到70%时ROI不降反升）
       连衣裙拉新：日花费 ¥6,000→¥9,000 → ROI 预计 3.0-3.2（+50%预算历史ROI略降5%）
       总体：ROI 从 3.1 到约 3.3-3.4 ✅，日花费不变
        
       置信度：中（基于3次类似调整的历史数据）
       风险：连衣裙拉新加50%预算可能撞日预算上限（当前上限¥8,000）
       
       建议：先加 ¥2,000 而不是 ¥3,000，观察3天再决定。"
```

---

## 二、模拟引擎

### 2.1 模拟类型

| 类型 | 示例 | 模拟逻辑 |
|------|------|---------|
| 预算调整 | "把A的¥1,000挪给B" | 历史预算弹性（预算变化→ROI变化） |
| 出价调整 | "关键词降20%" | 历史出价弹性（出价变化→ROI/花费变化） |
| 计划启停 | "暂停A，开启B" | A剩余计划效果+B历史启动期效果 |
| 批量组合 | "降A词+加B预算+换C素材" | 各维度弹性叠加→综合预判 |

### 2.2 弹性计算

```
预算弹性 = 历史ROI变化% / 历史预算变化%

例：连衣裙拉新过去3次加预算时：
  预算+20% → ROI -3%  弹性 = -0.15
  预算+15% → ROI -1%  弹性 = -0.07
  预算+25% → ROI -2%  弹性 = -0.08
  平均弹性 = -0.10

模拟：预算+50% → 预计ROI变化 = 50% × (-0.10) = -5%
     当前ROI 3.2 → 模拟ROI = 3.2 × 0.95 ≈ 3.04
```

### 2.3 置信度

| 条件 | 置信度 |
|------|:--:|
| 同对象 ≥ 5 次类似操作记录 | 高 🔵 |
| 同对象 2-4 次记录，或同类对象 ≥ 5 次 | 中 🟡 |
| 无直接记录，仅行业参考 | 低 🟠 |
| 无任何参考数据 | 无法模拟 |

### 4.2 模拟算法

```
对每个操作：
  1. 匹配历史弹性数据
     · 有直接记录 → 使用直接弹性
     · 无直接记录 → 使用同类对象弹性（同品类计划/同类型关键词）
     · 无同类 → 使用行业基准弹性

  2. 计算子操作预期效果
     预期变化 = 操作幅度 × 弹性系数 × (1 - 衰减因子^相似次数)

  3. 多操作叠加
     独立操作 → 效果相加
     关联操作 → 效果相乘（降出价+降预算对ROI可能互相放大）

  4. 风险检测
     · 预算撞线风险
     · ROI跌破底线风险
     · 花费骤增风险
     · 与历史模式冲突风险
```
