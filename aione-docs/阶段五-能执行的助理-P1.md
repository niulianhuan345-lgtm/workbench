## 2.4 关键词批量优化 — 升级文档

> **升级概述：** 在现有关键词优化建议Skill的基础上，增加"一键执行"能力，让分析到执行在同一次对话中闭环。
>
> **升级前：** Skill仅输出优化建议，用户需手动逐个修改关键词出价/匹配方式。
> **升级后：** Skill输出建议后，用户说"执行"即可逐项自动修改。

│ └──────┬───────────┘   │

### 触发话术

分析建议输出后，用户可使用以下话术触发执行：

| 执行范围 | 话术示例 |
|---------|---------|
| 全部执行 | "执行" / "全部执行" / "按建议改" / "好的，改吧" |
| 选择性执行 | "执行1、3、5" / "只改出价，匹配方式不改" / "只执行ROI低的" |
| 逐项确认 | "逐项确认" / "一个一个来" / "每个让我确认" |

### 执行规则

1. **默认行为**：用户说"执行"时，默认全部执行所有建议项
2. **逐项确认模式**：用户说"逐个确认"时，每项展示修改前后对比，用户确认一个执行一个
3. **选择性执行**：支持按序号选择（"执行第1、3条"）或按条件选择（"只改出价"）
4. **安全限制**：
   - 单次执行不超过50个关键词
   - 出价调整幅度超过100%时，该项单独确认
   - 匹配方式从精确→广泛时，提示流量变化预估

## 安全机制

| 机制 | 触发条件 | 行为 |
|-----|---------|------|
| 大额变更确认 | 出价变化 > 100% | 该项单独二次确认 |
| 匹配放宽提醒 | 精确→广泛 | 提示"流量可能增长3-5倍" |
| 数量限制 | > 50个关键词 | 提示"建议分批执行" |
| 执行锁定 | 关键词正在被修改 | 跳过并提示 |
| 回滚窗口 | 所有执行 | 5分钟内可撤销全部变更 |

---

## 技术实现要点

1. **异步执行**：逐项调用关键词修改API，使用进度回调
2. **幂等性**：重复执行同一建议不会导致重复修改（检查当前值是否已为目标值）
3. **失败重试**：单项失败自动重试1次，仍失败则跳过并汇总
4. **操作日志**：每次执行写入2.6操作效果追踪，记录修改前后值

## 与现有Skill的集成

- **触发时机**：在现有Skill的Step 4输出建议之后
- **向后兼容**：不影响现有分析逻辑，用户可选择不执行（仅查看建议）
- **执行能力依赖**：关键词出价修改API、关键词匹配修改API
- **追踪依赖**：2.6 操作效果追踪（记录执行日志）

## 安全机制

| 机制 | 触发条件 | 行为 |
|-----|---------|------|
| 改前/改后对比 | 所有执行 | 必须展示对比表 |

## 技术实现要点

1. **原子性**：全部成功或全部失败（如非原子则分批提交，失败项汇总）
2. **执行顺序**：先减后加（先降低效预算释放额度，再加高效预算）
3. **预算冲突检测**：检查账户余额/日预算是否足够
4. **操作日志**：每次执行写入2.6操作效果追踪，关联执行前后数据
5. **验证提示**：执行后自动计算建议验证时间，到时主动提醒

> **升级概述：** 在现有计划优化分析Skill基础上，为每个优化建议添加"一键执行"入口。核心理念：分析→建议→执行 在同一次对话中完成。

## 新增内容：优化建议附带执行入口

### 核心设计理念

```
分析 → 建议 → 执行
  └────── 同一次对话 ──────┘
```

用户完成计划分析后，无需切换到计划列表手动操作，直接在对话中完成优化动作。

### 工作流变更

```
现有工作流：
  Step 1: 获取计划数据
  Step 2: 多维度分析（ROI/花费/转化/趋势）
  Step 3: 生成优化建议列表
  Step 4: 输出分析报告（现有终点）

新增工作流（Step 4 之后）：
  Step 5: 用户选择执行项
  Step 6: 逐项/批量执行优化操作
  Step 7: 执行结果汇总 + 写入追踪
```

## 安全机制

| 机制 | 说明 |
|-----|------|
| 上下文关联 | 用户指令必须在分析报告上下文中，避免误操作无关计划 |
| 模糊指令确认 | "把ROI低的都停了" 这类模糊指令先列出匹配项再确认 |
| 冲突检测 | 同一计划有多个建议时（如暂停vs降价），提示用户选择 |
| 执行计数限制 | 单次执行不超过10个计划操作 |
| 回滚 | 5分钟内可撤销本次所有执行 |

## 技术实现要点

1. **上下文保持**：分析报告数据保持在对话上下文中，用户指令基于此上下文解析
2. **指令消歧**：
   - "这个" → 最近讨论的计划
   - "ROI低的" → 重新匹配分析报告中的计划
   - "全部" → 分析报告中的所有建议
3. **执行依赖**：调用5.7批量操作引擎执行暂停/改预算/改出价等操作
4. **操作追踪**：每次执行写入2.6操作效果追踪

## 1. 背景与目标

### 1.1 背景

广告投放人员在万相台无界平台中创建推广计划，需要依次穿越7个产品线选择、策略模版匹配、出价方式设定、预算配置、人群定向等多个步骤。当前纯GUI操作门槛高、流程繁琐：一个中等复杂度的计划创建需要点击15-20次，耗时约5-8分钟。新手上手尤其困难——他们不知道"趋势明星"和"搜索卡位"的区别，不知道该选OCPC还是手动出价。

用户在对话中会说："帮我建个计划"、"给我的新品投一下关键词"、"618大促要加一条人群推广计划"。AIONE需要理解这些自然语言诉求，通过对话逐步收敛参数，最终输出结构化的计划创建方案。

### 1.2 目标

1. **降低创建门槛**：让用户用自然语言描述需求即可启动创建流程，无需记忆平台菜单和选项
2. **智能引导**：根据产品线和策略模版的兼容关系，动态生成问题路径，不展示无关选项
3. **默认推荐**：每一步给出合理默认值，用户可直接确认跳过
4. **结构化输出**：对话结束后生成完整参数清单，供用户确认后调用API创建

## 关键规则

### 规则1：逐步引导，一次一问
每轮对话只推进一个步骤。不要在一条消息里问多个步骤的问题。用户主动给出多个参数时可以跳过对应步骤。

### 规则2：每条选项附解释
每个选项搭配一句话说明（10字以内）。用emoji做视觉区分。

### 规则3：永远有默认推荐
每一步必须给出默认推荐值，用户可直接回复"可以"、"行"、"OK"确认。

### 规则4：支持中途修改
用户在任意步骤说"等一下，我想改XX"，回退到对应步骤重新设置，已确认的其他参数保留。

### 规则5：口语化理解
- "烧钱" = 预算相关
- "投产"、"ROI" = 控投产比策略
- "直通车" = 关键词推广
- "引力魔方" = 人群推广

### 规则6：计划命名规范
自动生成计划名格式：`{策略模版中文}-{出价策略中文}-{MMDD}`，如"趋势明星-OCPC-0528"。

## 1. 背景与目标

### 1.1 背景

关键词是搜索广告的核心资产。投手日常工作中最高频的操作就是关键词管理：添加新词、删除无效词、调整出价、切换匹配方式、设置否定词。一个中等规模计划通常包含50-200个关键词，批量操作频繁。

当前痛点：
- 批量改价要逐行操作或使用excel导入导出，流程割裂
- 自然语言指令如"把品牌词全改成精准匹配"需要投手手动筛选、逐个修改
- "给618计划加几个竞品词"——投手需要先研究竞品、再手动添加
- 无法快速预览修改影响面

### 1.2 目标

1. **自然语言驱动**：用户用口语描述操作意图，AIONE理解意图、提取参数、展示预览、确认后执行
2. **批量智能操作**：支持按类型（品牌词/竞品词/类目词等）、按计划、按出价范围等维度批量筛选和修改
3. **安全确认机制**：模糊指令（如"把出价降一降"）必须先明确范围和目标值，确认后再执行
4. **关键词推荐**：支持基于商品信息推荐竞品词、长尾词、趋势词

## 3. 功能设计

### 3.1 核心操作类型

AIONE支持以下5类关键词操作：

| 操作 | 说明 | API依赖 |
|------|------|---------|
| 添加关键词 | 在指定计划/单元下新增关键词，设置出价和匹配方式 | 万相台关键词创建API |
| 删除关键词 | 从计划/单元中移除指定关键词 | 万相台关键词删除API |
| 修改出价 | 调整关键词的CPC出价（支持绝对值/百分比/目标值） | 万相台关键词更新API |
| 修改匹配方式 | 切换广泛/精准/短语/中心词匹配 | 万相台关键词更新API |
| 设置否定词 | 添加精确否定词或短语否定词到计划/单元 | 万相台否定词设置API |

### 3.2 核心流程

```
用户输入自然语言指令
    │
    ▼
[步骤1] 意图识别与参数提取
    ├── 识别操作类型：添加/删除/改价/改匹配/否定词
    ├── 提取目标范围：哪个计划？哪些关键词？
    ├── 提取目标值：新出价？新匹配方式？
    └── 判断是否需要进一步澄清
    │
    ▼
[步骤2] 澄清与确认（按需）
    ├── 范围模糊 → "你是指哪个计划？当前账户有3个计划包含'连衣裙'"
    ├── 操作量大 → "这将影响45个关键词，确认继续？"
    └── 值不明确 → "出价降到2元还是降2元？"
    │
    ▼
[步骤3] 生成操作预览
    ├── 以表格展示受影响关键词列表（前10条+总数）
    ├── 标注每条关键词的变更前后对比
    └── 提示"共影响N个关键词，确认执行？"
    │
    ▼
[步骤4] 用户确认 → 调用API执行
    ├── 成功：返回执行结果摘要
    └── 失败：返回失败明细，支持重试
```

### 3.3 意图识别规则表

| 用户说法 | 操作类型 | 提取逻辑 |
|---------|---------|---------|
| "加词/添加关键词/新增" | 添加 | 提取关键词文本+所属计划+出价+匹配方式 |
| "删除/去掉/移除" | 删除 | 提取关键词/关键词类型+所属计划 |
| "改出价/出价调到/降价/提价" | 改价 | 提取新出价或调整幅度+目标词范围 |
| "改匹配/改成精准/切换匹配" | 改匹配 | 提取新匹配方式+目标词范围 |
| "否定/屏蔽/不想要" | 否定词 | 提取否定词文本+精确/短语 |

### 3.4 关键词类型识别（用于批量操作）

| 类型 | 识别规则 | 示例 |
|------|---------|------|
| 品牌词 | 包含品牌名（需维护品牌词库） | "Nike"、"华为" |
| 竞品词 | 竞品品牌名（需维护竞品词库） | 竞品品牌列表匹配 |
| 类目词 | 通用品类名 | "连衣裙"、"手机壳" |
| 长尾词 | 4个词以上组成 | "2024夏季新款碎花连衣裙" |
| 核心词 | 用户手动标记或高转化词 | 计划中标记的核心关键词 |
| 人群词 | 包含人群描述 | "学生"、"上班族" |

### 3.5 安全规则

| 规则 | 阈值/条件 | 行为 |
|------|----------|------|
| 模糊范围 | 用户未指明具体计划，且账户内存在多个匹配计划 | 必须列出候选计划让用户选择 |
| 大影响面 | 受影响关键词 > 20个 | 展示前10条+总数，要求确认 |
| 大影响面 | 受影响关键词 > 50个 | 额外提醒"这是一个批量操作，将影响XX个关键词" |
| 出价超限 | 新出价 > 当前出价的200% 或 < 20% | 提示风险并确认 |
| 删除保护 | 删除核心词（高转化词） | 提示"该词近7天转化率XX%，确认删除？" |
| 空结果 | 筛选条件未匹配到任何关键词 | 提示"未找到匹配的关键词，请调整条件" |

# 关键词操作执行

## 触发条件

**必须触发**：用户表达了对关键词进行操作的意图——添加、删除、修改出价、修改匹配方式、设置否定词。关键词包括但不限于：用户主动输入的关键词文本、按类型指代（品牌词/竞品词/类目词/长尾词/核心词/人群词）。

**不触发**：用户仅查看关键词报表、分析数据等只读场景。

---

## 核心工作流

### 步骤一：意图识别

从用户消息中解析三个核心要素：

| 要素 | 说明 | 示例 |
|------|------|------|
| **操作类型** | add / delete / update_bid / update_match / add_negative | "加词"→add；"删除"→delete；"改出价"→update_bid |
| **目标范围** | 哪个计划？哪些关键词？ | "连衣裙计划"、"品牌词"、"出价>3元的词" |
| **目标值** | 新出价/新匹配方式/新关键词文本 | "1.8元"、"精准匹配"、"Nike" |

### 步骤二：范围澄清（按需）

当以下条件满足时，必须追问澄清：

```
IF 目标计划不明确 AND 账户内匹配的用户描述的计划 > 1:
    列出候选计划，让用户选择

IF 操作类型涉及"改出价" AND 目标值不明确（如"降一降"）:
    追问具体目标值，给出参考建议

IF 受影响关键词数 > 20:
    展示前10条 + 总数，要求确认

IF 受影响关键词数 > 50:
    额外提醒"这是批量操作，将影响XX个关键词"
```

### 步骤三：生成操作预览

以表格形式展示变更预览：

**修改类操作预览模板：**
```
| 关键词 | 当前值 | → 新值 | 所属计划 |
|--------|-------|--------|---------|
| xxx    | xxx   | xxx    | xxx      |
...
共 N 个关键词受影响。确认执行？
```

**添加类操作预览模板：**
```
| 关键词 | 出价 | 匹配方式 | 所属计划 |
|--------|------|---------|---------|
| xxx    | xxx  | xxx     | xxx      |
...
确认添加？
```

**删除类操作预览模板：**
```
| 关键词 | 当前出价 | 近7天转化 | 所属计划 |
|--------|---------|----------|---------|
| xxx    | xxx     | xxx      | xxx      |
...
共 N 个关键词将被删除。确认删除？
```

### 步骤四：安全校验

执行前自动检查以下规则：

| 校验项 | 条件 | 行为 |
|--------|------|------|
| 出价异常 | 新出价 > 当前×2 或 < 当前×0.2 | ⚠️ 提示风险后确认 |
| 删除保护 | 被删词近7天转化率 > 计划均值×1.5 | ⚠️ 提示"该词转化表现好" |
| 匹配降级 | 精准→广泛（可能带来无效流量） | ⚠️ 提示"可能增加无效点击" |

### 步骤五：API执行

用户确认后调用对应API：
- 添加：万相台关键词创建接口
- 删除：万相台关键词删除接口
- 修改：万相台关键词更新接口
- 否定词：万相台否定词设置接口

成功返回摘要，失败返回明细。

## 关键规则

### 规则1：永远先预览再执行
不经过预览确认，绝不直接修改关键词。哪怕只影响1个词也要展示"变更前后对比"。

### 规则2：模糊指令必须澄清
"降一降"、"优化一下"、"调一调"等模糊表述，必须追问具体目标值和范围。

### 规则3：竞品词推荐逻辑
用户说"加竞品词"时：
1. 识别推广商品类目
2. 从竞品词库中匹配同类目竞品品牌
3. 给出3-5个推荐，附建议出价（参考类目均价）
4. 让用户勾选或全选

### 规则4：关键词类型识别
支持用户按关键词类型指代批量目标：
- "品牌词" → 匹配品牌词库
- "竞品词" → 匹配竞品词库
- "类目词" → 匹配通用品类关键词
- "长尾词" → 4个词以上组成的搜索词
- "核心词" → 标记为核心的关键词

### 规则5：百分比调整
用户说"提高10%"、"降低20%"时，基于当前出价计算新出价，预览时同时显示百分比变化和绝对值变化。

## 出价智能调控 - 需求文档

> 版本：v1.0 | 日期：2026-05-28 | 作者：AIONE产品组

## 1. 背景与目标

### 1.1 背景

出价是广告投放中最核心也最频繁的调控动作。投手每天要面对"出价太高烧太快"、"出价太低没量"、"不同时段转化率不同需要分时折扣"等复杂决策。万相台无界提供了丰富的出价控制手段——手动出价、OCPC、最大化拿量、控投产比、分时折扣、人群溢价、资源位溢价——但对投手而言，理解和组合使用这些手段有较高门槛。

投手的口语表达往往很抽象："烧不动了"（实际意思可能是出价偏低导致曝光不足，需要观察ROI后决定是否提价）、"跑飞了"（花费速度远超预期，需要降低出价或切换控投产比）、"晚上效果好，晚上多投点"（需要设置分时折扣）。

AIONE需要将这些口语化表达翻译为具体的出价调控操作，并在执行前给出影响预估。

### 1.2 目标

1. **口语理解**：识别"烧不动了"、"跑飞了"、"成本太高"、"没量"等口语，映射到具体调控策略
2. **影响预估**：每次操作前给出预算消耗变化、曝光量变化、预计ROI变化的定性预估
3. **多维调控**：支持出价调整、出价策略切换、分时折扣设置、人群溢价调整、资源位溢价调整
4. **安全边界**：防止用户误操作导致预算失控，设置出价和预算的保护上限

# 出价智能调控

## 触发条件

**必须触发**：用户表达了对出价、预算、出价策略、分时折扣、人群溢价或资源位溢价的调整意图，尤其是用口语化的方式描述投放效果异常。

**核心触发信号**（口语映射）：
- "烧不动了" / "没曝光" / "跑不出去" → 曝光不足，需提价或放宽策略
- "跑飞了" / "烧太快" / "花费太快" → 消耗异常加速，需控速
- "成本太高" / "转化成本高" → 转化成本超预期，需OCPC或降价
- "没量" / "量太少" → 曝光/点击不足
- "ROI太差" / "投产不行" → 投产比不理想
- "晚上多投" / "XX时段效果好" → 分时折扣调整
- "XX人群加溢价" → 人群溢价调整

---

## 核心工作流

### 步骤一：诊断与意图解析

收到用户口语化指令后，先调取目标计划的近24h核心数据（消耗、曝光、点击、转化、CPC、ROI），做快速诊断：

```
获取目标计划近24h数据
    ↓
对比该计划近7天均值 / 类目均值
    ↓
识别异常：消耗速度异常？曝光不足？ROI下滑？转化成本上升？
    ↓
匹配调控策略
```

### 步骤二：策略推荐

根据诊断结果推荐1-3个调控方案：

| 诊断结论 | 推荐方案1（首选） | 方案2 | 方案3 |
|---------|----------------|------|------|
| 曝光不足（出价<均价） | 提价至类目均价 | 切换最大化拿量 | 放宽人群定向 |
| 消耗过快（>平时3倍） | 切换控投产比 | 直接降价20% | 降日预算 |
| 转化成本高 | 设OCPC目标成本 | 降价+精准匹配 | 否决不相关词 |
| ROI低 | 切换控投产比 | 降低CPC出价 | 分时优化 |
| 转化集中某时段 | 分时折扣提高该时段 | — | — |

### 步骤三：影响预估

每个方案附三维影响预估（定性）：

```
📊 影响预估：
| 方案 | 日消耗 | 曝光量 | 预期ROI |
|------|-------|-------|---------|
| 当前 | {当前值} | {当前值} | {当前值} |
| 方案1 | ↑/↓/→ xx | ↑/↓/→ xx | ↑/↓/→ xx |
```

### 步骤四：用户确认

用户选择方案后，展示具体执行参数，请求确认：

```
将执行：{计划名}
操作：{具体操作描述}
---
变更详情：
- 出价策略：{旧} → {新}
- 出价值：{旧} → {新}
- 日预算：{旧} → {新}（如涉及）
---
确认执行？
```

### 步骤五：API执行

调用对应API，返回执行结果。关键操作（出价策略切换、分时折扣设置）建议用户"1小时后查看数据"。

## 关键规则

### 规则1：口语映射优先
收到口语化表达时，必须先拉数据诊断，再推荐方案。不要直接假设用户的意图。

### 规则2：每次展示影响预估
任何出价/预算相关操作，必须附预估。格式：消耗↑/↓/→、曝光↑/↓/→、ROI↑/↓/→。

### 规则3：安全边界
| 规则 | 阈值 | 行为 |
|------|------|------|
| 出价涨幅过大 | 新出价 > 当前×2 | ⚠️"出价翻倍，日消耗可能大幅上升" |
| 日预算翻倍 | > 当前×2 | ⚠️"预算翻倍，请确认账户余额充足" |
| 分时折扣极端 | >200% 或 <20% | ⚠️"极端折扣可能导致不稳定" |
| 人群溢价过高 | >100% | ⚠️"高溢价可能挤压其他人群流量" |

### 规则4：出价策略切换条件校验
- 手动CPC→OCPC：需近7天转化≥10个，否则提示数据不足
- OCPC→控投产比：需有ROI数据支撑
- 任何策略→最大化拿量：必须确认日预算上限

### 规则5：批量操作特殊处理
跨计划操作时，逐一列出每个计划的影响明细，不允许"全部应用"一键执行。

### 规则6：分时折扣模板
提供3个预设模板：全天均衡、晚间高峰、白天主投。用户可基于模板微调。

---

## 异常处理

| 异常场景 | 处理方式 |
|---------|---------|
| 数据不足无法诊断 | "该计划数据量较少（近24h曝光<100次），建议再观察24h或手动设置。" |
| 账户余额不足以支撑预算提升 | "提升后预计日消耗X元，当前余额Y元仅够Z天。建议先充值。" |
| API执行失败 | 返回失败原因，保留参数供重试 |
| 计划暂停中 | "该计划当前处于暂停状态，请先开启计划。" |
| 跨计划操作部分失败 | 列出成功/失败明细 |
| 策略切换条件不满足 | 说明不满足原因并给出替代方案 |
